## 4. 主窗口视觉审计

### 4.1 总体判断

主窗口的信息架构正确，但视觉表现接近 WPF 默认控件集合。当前主要问题不是功能布局错误，而是缺少产品级设计系统和清晰的操作层级。

现有三栏结构应保留：

- 左侧：Receipt Queue。
- 中间：票据图像与 OCR 覆盖层。
- 右侧：OCR 和 Fields 审核。

顶部和底部需要重新建立操作层级，三栏内部需要统一表面、间距、选择状态和空状态。

### 4.2 顶部命令区

当前问题：

- 六个操作分成两行，但没有输入、分析、批量和导出分组。
- 所有可用按钮使用相同默认样式，主次操作难以区分。
- 禁用按钮的文字对比度过低。
- 状态文字放在按钮右侧的大块空白区域中，和命令栏缺少结构关系。
- 状态文字被后续操作覆盖，不能持续表达 Worker 是否可用。

阶段 1 和阶段 2 的处理方向：

- 建立 Primary、Secondary、Ghost 和 Danger 控件层级。
- 将命令按“导入、分析、批量、导出”分组。
- 将 Worker 状态与临时操作消息分开。
- 对 Processing 使用明确的活动状态，不只更新一句文字。

### 4.3 票据队列

当前问题：

- 文件名和阶段文字尺寸较小，扫描效率一般。
- 状态圆点使用系统颜色，色彩饱和度和语义不统一。
- Pending、OCR Review、Field Review 和 Approved 之间主要依靠圆点和英文文字。
- 选中背景使用系统浅蓝色，与计划中的产品色不一致。
- 队列为空时完全空白。
- `Sort Queue` 始终占据底部整行，视觉权重偏高。

值得保留：

- 文件名和状态采用两行结构。
- 状态变化后不自动排序，符合现有操作规则。
- 选中项能同步更新图像和审核面板。

### 4.4 票据工作区

当前问题：

- 工作区是接近纯白的大平面，票据纸张与背景层级不明显。
- 图片顶部对齐后，下方存在大量无信息空白。
- 空状态没有“导入图片开始”的引导。
- OCR 框使用高饱和绿色和红色，视觉噪声较大。
- 低置信度、选中和普通 OCR 框之间需要更系统的表达。

值得保留：

- 图片与 OCR 框的同步定位有效。
- OCR 框与右侧行选择可以联动。
- 图像可在中间区域保持主要视觉地位。

### 4.5 审核面板

当前问题：

- `GroupBox` 和系统 Tab 呈现传统桌面工具外观。
- OCR 行的序号、文本、置信度和修正状态层级不足。
- OCR 列表出现横向滚动条，影响阅读连续性。
- Fields 页采用固定 110 + 160 宽度，在窄面板中可用，但缺少弹性。
- 字段置信度说明靠近下一行时容易产生归属歧义。
- 冲突状态主要依赖红色边框，不满足“不可只依赖颜色”的目标。
- 从队列重新选择 Field Review 票据时仍停留在 OCR 页，需要用户手动切换 Fields。
- 审核区为空时没有解释当前需要做什么。

值得保留：

- OCR 和 Fields 分成两个清晰阶段。
- 字段输入使用可编辑 ComboBox，兼顾建议和自由输入。
- 置信度和 OCR 引用信息已经存在，可以通过排版强化。

### 4.6 底部操作区

当前问题：

- 快捷键说明是一整行长句，扫描成本较高。
- `Next Receipt`、`Confirm OCR` 和 `Approve Fields` 的按钮样式相同。
- 当前阶段的主操作不够突出。
- 禁用状态较淡，按钮仍占据较大视觉空间。

值得保留：

- 三个按钮与审核流程的对应关系清楚。
- 快捷键设计合理。
- Confirm OCR 后自动移动到下一张票据，适合批量审核。

## 5. 业务弹窗视觉审计

### 5.1 Edit OCR Text

已实机验证。

当前问题：

- 视觉完全依赖系统默认 Window、TextBox 和 Button。
- Header 是说明句，但与输入区域的层级接近。
- Save 和 Cancel 的主次差异不明显。
- 输入框很宽，但窗口高度较低，长文本编辑空间有限。

保留项：

- 内容简单，操作路径直接。
- 默认按钮和取消按钮语义清楚。
- 初始文字自动选中，便于直接覆盖。

### 5.2 Batch Fill

已实机验证。

当前问题：

- 中文字段、英文范围选项和英文按钮混用。
- 顶部说明、管理建议、范围选择和覆盖选项挤在一个区域。
- 表单采用紧凑双列布局，但标签与输入控件间距不统一。
- `管理建议` 与主要批量填写流程的关系不够清楚。
- Apply 与 Cancel 视觉权重相同。
- 滚动条使用系统默认样式，与主窗口缺少一致性。

保留项：

- 非空值才应用的规则已明确显示。
- Selected 与 All Analyzed 的范围选择直观。
- Overwrite 是显式选择，没有默认开启。

### 5.3 Suggestions

已实机验证。

当前问题：

- Tab、GroupBox、ListBox 和按钮均为默认样式。
- 空建议列表缺少解释和引导。
- 删除操作与普通操作视觉权重接近。
- “已有建议”和“新增建议”嵌套 GroupBox，层级显得厚重。
- 中文界面中仍使用 Save 和 Cancel。

保留项：

- 按建议类别分 Tab 的结构合理。
- 新增和删除区域分离。
- 空数据状态不会导致布局崩坏。

### 5.4 Review Excel Export

已实机验证，并覆盖重复单号场景。

当前问题：

- 目标路径很长，成为弹窗顶部最强视觉元素。
- 摘要信息是一整句英文，重复数和已选择数不易快速扫描。
- DataGrid 使用系统默认表头、网格和选中样式。
- `Append New Only`、`Append All`、`Append None`、`Export Selected` 和 `Cancel` 五个按钮层级接近。
- 重复状态只有表格文字，没有更明显但克制的行状态。
- 窗口中部留白较大，数据量少时显得松散。

保留项：

- 导出前提供逐条审核是正确的安全设计。
- 重复单号默认不勾选。
- 用户仍可明确选择是否追加重复项。
- 本次取消后没有写入 Excel。

## 6. 交互与可访问性基线

### 6.1 当前做得较好的部分

- 主要按钮和列表具有可访问名称。
- OCR 行能暴露文字和置信度。
- Fields 能暴露字段标签、输入控件和来源说明。
- Save/Apply 等窗口设置了默认按钮。
- Cancel 设置了取消语义。
- 主窗口已有快捷键绑定。
- 禁用按钮能够被辅助树识别为 Disabled。

### 6.2 后续必须改善的部分

- 建立统一且可见的键盘焦点样式。
- 冲突和错误不能只依赖红色。
- 状态圆点必须配合文字或图形语义。
- Disabled 文字仍需达到可读对比度。
- 空状态需要向辅助技术提供说明。
- 检查自定义 ControlTemplate 后是否保留 Automation 属性。
- 检查所有 Dialog 的 Tab 顺序。
- DataGrid 的勾选、重复状态和行选择需要保持键盘可操作。

- 四个业务弹窗共享设计系统。
- DataGrid、表单和按钮区统一。
- 文案语言一致性。
- 高 DPI、最小窗口和长内容校准。

## 8. 阶段 1 输入条件

阶段 1 可以开始，当前没有技术阻塞。

建议采用以下方案：

- 主题：高质量浅色主题。
- 方向：现代 Windows / 克制 Fluent 风格。
- 中性色：冷灰体系。
- 强调色：单一、低噪声蓝色。
- 字体：`Segoe UI Variable Text`，提供系统字体回退。
- 圆角：输入控件和按钮使用小圆角，面板使用中等圆角。
- 动效：仅 Hover、Pressed、Focus 和状态切换反馈。
- 第一轮不翻译现有中英文文案，先避免把文案改动混入视觉基础提交。
- 第一轮不引入第三方 WPF UI 库。
